## 3. Skill frameworks, certifications, and roadmap repos

### NIST NICE Framework (official)

- The NICE Framework is "a nationally focused resource to help employers develop their cybersecurity workforce" and "establishes a common lexicon that describes cybersecurity work and workers," applying across public, private and academic sectors ([NICCS / CISA](https://niccs.cisa.gov/tools/nice-framework)).
- Components: **Work Role Categories** (high-level grouping of common cybersecurity functions), **Work Roles** (a grouping of work someone is responsible for — "not synonymous to job titles"), **TKS Statements** (Task, Knowledge, Skill building blocks), and **Competency Areas** (clusters of related Knowledge and Skill statements) ([NICCS / CISA](https://niccs.cisa.gov/tools/nice-framework)).
- Current NICE Framework Components version: **2.2.0, dated April 28, 2025**; the framework structure itself is NIST SP 800-181 Revision 1, published November 2020 ([NIST](https://www.nist.gov/itl/applied-cybersecurity/nice/nice-framework-resource-center/nice-framework-current-versions)).
- The seven Work Role Categories, with 52 Work Roles: **Oversight & Governance; Design & Development; Implementation & Operation; Protection & Defense; Criminal Investigation; Intelligence; Cyber Effects** ([NIST presentation "Building a Job-Ready Cybersecurity Workforce," hosted by ENISA](https://www.enisa.europa.eu/sites/default/files/all_files/4_Wetzel_NIST.pdf)).
- SP 800-181r1 confirms the older 2017 categories ("securely provision," "oversee and govern," "protect and defend," "analyze," etc.) were deprecated and the Task/Knowledge/Skill/Work Role appendices removed, with current components now published via the NICE Framework Resource Center ([NIST SP 800-181r1 PDF](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-181r1.pdf)).
- Machine-readable components (Work Roles + Categories spreadsheet) are downloadable from NIST, e.g. [NICE Framework Components v2.1.0 XLSX](https://www.nist.gov/system/files/documents/2025/12/31/NICE%20Framework%20Components%20v2.1.0.xlsx).
- Career exploration tool: [Cyber Career Pathways Tool](https://niccs.cisa.gov/tools/cyber-career-pathways-tool).

## 4. What makes a GitHub repo actually help a resume

**GitHub's own guidance**

- Link your GitHub profile on your resume: "Including a link to your GitHub profile in your resume showcases your skills and experience to potential employers," and after following the steps "hiring managers should have a good sense of your technical skills" ([GitHub Docs](https://docs.github.com/en/account-and-profile/tutorials/using-your-github-profile-to-enhance-your-resume)).
- Write a short professional bio giving "a high-level overview of who you are" and "an indication of what kind of work you're looking for," e.g. "Hello! My name is Mona and I'm looking for work as a front end developer" — plus a profile picture and a link to your personal website/portfolio ([GitHub Docs](https://docs.github.com/en/account-and-profile/tutorials/using-your-github-profile-to-enhance-your-resume)).
- Profile README should cover: an introduction, skills (languages, frameworks, tools), professional experience (including non-technical skills such as communication and empathy), your best projects, and achievements/certifications/awards ([GitHub Docs](https://docs.github.com/en/account-and-profile/tutorials/using-your-github-profile-to-enhance-your-resume)).
- Pin your best work: "You can pin gists and repositories to your profile so other people can quickly see your best work," and you may "select up to six repositories and gists, combined," reorderable by drag ([GitHub Docs](https://docs.github.com/en/account-and-profile/how-tos/profile-customization/pinning-items-to-your-profile)).
- README content standard: a README is "often the first item a visitor will see when visiting your repository" and typically covers what the project does, why it is useful, how to get started, where to get help, and who maintains/contributes ([GitHub Docs](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes)).
- Keep READMEs scoped — "only contain the necessary information for developers to get started using and contributing"; longer documentation belongs in wikis. GitHub surfaces READMEs from `.github/`, the root, or `docs/` (in that precedence), truncates content over **500 KiB**, and auto-generates a table of contents from headings ([GitHub Docs](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes)).
- A README added to the root of a public repo named the same as your username automatically appears on your profile page ([GitHub Docs](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes)).

**Community / career sources**

- A good README "helps you stand out among the large crowd of developers who put their work on GitHub," should be "fairly brief but detailed," and typically includes install/run instructions; improved documentation on the author's own project "improved engagement" and "helped other developers get involved" ([freeCodeCamp](https://www.freecodecamp.org/news/how-to-write-a-good-readme-file/)).
- Profile hygiene that matters: add a profile image ("often the first thing people notice"), fill in profile details for "credibility and discoverability" including a city/country location, and create a profile README (a public repo named exactly your username) answering who you are, project highlights, what you're currently working on or learning, and optionally hobbies — "keep it minimal but interesting" ([freeCodeCamp](https://www.freecodecamp.org/news/how-to-make-your-github-profile-stand-out/)).
- Resume mechanics: "List a phone number, email address, and if you have it, a link to your GitHub profile"; "Include personal projects" even if not for work or school, because "those projects are great places to showcase your talents… particularly if they're included in your GitHub, which you should include a link to"; and "if the project shows off skills which aren't present in another area of your résumé, list them" ([freeCodeCamp](https://www.freecodecamp.org/news/how-to-write-a-resume-that-works/)).
- Profile README extras used by standout profiles: a brief biography, a colorful header image, links to find you elsewhere on the web, and — if using GitHub "as a resume / portfolio" — a stats card via `github-readme-stats` ([GitHub on DEV](https://dev.to/github/10-standout-github-profile-readmes-h2o)).
- Cybersecurity-specific portfolio guidance: define the portfolio's goal (e.g. secure an entry-level cybersecurity role) and tailor content to the audience — an aspiring pentester emphasizes ethical hacking and vulnerability assessment, a compliance-focused candidate emphasizes regulatory knowledge and documentation; treat the portfolio as "a professional narrative." Use a combination of a personal website, GitHub repositories (ideal for "coding projects" and "scripts") and LinkedIn; prioritize navigation, visual appeal and responsiveness; include a PDF version for offline sharing and keep formats consistent ([Cybersecurity District](https://www.cybersecuritydistrict.com/a-step-by-step-guide-to-building-a-cybersecurity-portfolio/)).

## 5. GitHub Pages setup reference (official docs)

- Documentation hub: [GitHub Pages documentation](https://docs.github.com/en/pages) and [Getting started with GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages).
- **Quickstart (user site):** GitHub Pages can be used to "showcase some open source projects, host a blog, or even share your résumé." Steps: create a **New repository** named `username.github.io` (your exact username; example: `octocat` → `octocat.github.io`), choose visibility, toggle **Add README** on, **Create repository** → repo **Settings** → **Code and automation ▸ Pages** → under **Build and deployment ▸ Source** select **Deploy from a branch**, pick the publishing branch, then visit `username.github.io`. Changes "can take up to 10 minutes to publish after you push changes to GitHub" ([GitHub Docs Quickstart](https://docs.github.com/en/pages/quickstart)).
- **Plan requirements:** Pages is available in public repositories with GitHub Free and GitHub Free for organizations, and in public *and private* repositories with GitHub Pro, Team, Enterprise Cloud and Enterprise Server ([GitHub Docs Quickstart](https://docs.github.com/en/pages/quickstart)).
- **Creating a site in an existing repo:** choose a publishing source — either "a dedicated branch and folder containing the site source files" or "a custom GitHub Actions workflow"; create the site's entry file, which must be one of `index.html`, `index.md`, or `README.md`; if the owning account uses GitHub Free, the repository must be public. Note the security warning: "GitHub Pages sites are publicly available on the internet, even if the repository is private" — remove sensitive data before publishing ([GitHub Docs: Creating a GitHub Pages site](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)).
- Hands-on guided course: [skills/github-pages](https://github.com/skills/github-pages) — "Create a site or blog from your GitHub repositories with GitHub Pages."
